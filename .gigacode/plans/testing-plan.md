# План тестирования SIS.SITE v1.0

## 📋 Обзор проекта

**SIS.SITE** — простая система управления контентом (CMS) с многоуровневой системой доступа:
- **Уровень 0** — Гость (только просмотр)
- **Уровень 1** — Пользователь (добавление новостей)
- **Уровень 2** — Модератор (редактирование, удаление)
- **Уровень 3** — Администратор (полный доступ)

---

## 🎯 Цель тестирования

Проверить **все функциональные компоненты** системы в правильной последовательности:
1. Запуск сервера
2. Базовые страницы (гостевой уровень)
3. Система доступа (PermissionManager + AccessLevels)
4. API endpoints (login, news CRUD)
5. Редактор новостей (news-form + card-constructor)
6. Интеграция всех компонентов

### Уровень 6: Интеграция компонентов

#### TC-6.1: Полный workflow "Создание новости"
1. Пользователь входит (уровень ≥ 1)
2. Открывает `/news.html`
3. Нажимает "Создать новость"
4. Заполняет форму
5. Нажимает "Опубликовать"
6. Новость появляется в списке

#### TC-6.2: Полный workflow "Удаление новости"
1. Администратор входит (уровень = 3)
2. Открывает `/news.html`
3. Видит кнопку "🗑️ Удалить" у каждой новости
4. Нажимает удаление
5. Новость исчезает из списка

#### TC-6.3: Полный workflow "Редактирование"
1. Администратор входит
2. Открывает отдельную новость
3. Редактирует поля
4. Сохраняет изменения
5. Изменения отображаются

## 🐛 Ожидаемые проблемы

1. **Проблемы с CORS** — добавить заголовки в `siss.py`
2. **Ошибки MIME-типов** — проверить `mimetypes.guess_type()`
3. **Проблемы с multipart/form-data** — проверить парсинг в `/save-news`
4. **Кэширование браузера** — использовать Ctrl+F5 при тестировании
