# Логика системы управления доступом (SIS.SITE v1.0)

## Цель
Кнопка "Получить доступ к файлам" должна появляться **только** при отсутствии доступа к localhost (сервер не отвечает), и исчезать, когда доступ есть. Кнопка нужна для обхода CORS-ограничений в офлайн-режиме.

---

## Ключевые принципы

1. **Это не про доступ пользователя** — это про доступ сайта к собственному функционалу вне сети
2. **Без доступа к localhost корс не даст работать с файлами** — сайт работать не сможет
3. **Проверка происходит один раз** и кэшируется — не на каждой странице
4. **Кнопка "Дать доступ" не делает запрос к серверу** — сразу выдает уровень 1 (для работы в офлайн режиме)

---

## Структура файлов

### access-init.js
- Загружается **ПЕРВЫМ** (до всех остальных скриптов)
- Просто импортирует `PermissionManager`, инициализация происходит автоматически
- Глобально: `window.permissionManager = pm`

### permission-manager.js
Основной модуль управления доступом.

#### Состояние
- `this.hasLocalhostAccess` — есть ли доступ к localhost
- `this.storageKey = 'permissions_granted'`
- Ключи localStorage:
  - `permissions_granted` — доступ выдан (пользователь нажал кнопку)
  - `localhost_checked` — проверка localhost уже проводилась
  - `localhost_has_access` — результат проверки (true/false)
  - `access_granted_via_button` — доступ выдан через кнопку (без проверки localhost)

#### Методы

**checkLocalhostAccess()**
- Если `access_granted_via_button === 'true'` → возвращает `true` сразу (проверка не нужна)
- Если есть кэш (`localhost_checked === 'true'`) → используем сохранённый результат
- Иначе делаем запрос к `/api/check-access` с таймаутом 2 секунды
- Сохраняем результат в localStorage

**requestAccess()**
- Вызывается при нажатии кнопки "Дать доступ"
- В офлайн режиме **сразу** выдаёт уровень 1 без запросов к серверу
- Возвращает `Promise<boolean>` → `true`

**grantPermission()**
- Сохраняет `permissions_granted = 'true'`
- Устанавливает `access_granted_via_button = 'true'`
- Устанавливает `localhost_checked = 'true'` и `localhost_has_access = 'false'`
- Скрывает кнопку и оверлей
- Добавляет класс `access-granted` к body

**init()**
1. Вызывает `checkLocalhostAccess()`
2. Если `hasLocalhostAccess === true` → скрываем кнопку, всё нормально
3. Если `hasLocalhostAccess === false` → показываем кнопку
4. Навешиваем обработчик клика на кнопку

---

### access-levels.js
Управление уровнями доступа.

#### Методы
- `getLevel()` — получить текущий уровень
- `setLevel(level)` — установить уровень
- Сохраняет в localStorage: `permissions_level`

---

### news-manager.js
Управление новостями.

#### Особенности
- **НЕ** загружает новости автоматически при инициализации
- Загрузка происходит только когда вызывается `loadNews()`
- Вызывается из `main.js` только на странице новостей

---

### main.js
Точка входа в приложение.

#### Логика инициализации
1. Создаёт `MainApp`
2. Вызывает `initComponents()`
3. Проверяет наличие `.add-news-btn` — если нет, то это **не страница новостей**
4. Если это страница новостей:
   - Инициализирует `NewsManager`
   - Вызывает `loadNews()`
   - Инициализирует `NewsForm`

---

## Логика работы

### Сценарий 1: Сервер запущен (доступ есть)
1. Проверка localhost → успешный запрос к `/api/check-access`
2. Сохраняем `localhost_checked = 'true'`, `localhost_has_access = 'true'`
3. Кнопка "Получить доступ" **не показывается**
4. Если есть сохранённый уровень доступа → загружаем новости
5. Если нет → пользователь не может работать с новостями

### Сценарий 2: Сервер не запущен (доступа нет)
1. Проверка localhost → таймаут/ошибка
2. Сохраняем `localhost_checked = 'true'`, `localhost_has_access = 'false'`
3. **Показываем кнопку** "Получить доступ"
4. Пользователь нажимает кнопку:
   - Устанавливаем `access_granted_via_button = 'true'`
   - Устанавливаем уровень 1
   - Скрываем кнопку
   - Теперь можно работать с новостями (но запросы к `/get-news` будут падать — это нормально для офлайн режима)

### Сценарий 3: Пользователь уже нажал кнопку ранее
1. `access_granted_via_button === 'true'`
2. Пропускаем проверку localhost → сразу `hasLocalhostAccess = true`
3. Кнопка **не показывается**
4. Проверяем `permissions_granted` — если есть, загружаем новости

---

## Важные нюансы

1. **Кэш проверки localhost сохраняется** — проверка происходит только один раз
2. **При нажатии кнопки кэш не сбрасывается** — проверка localhost не будет повторяться
3. **Загрузка новостей происходит только на странице новостей** — проверка `.add-news-btn`
4. **Кнопка "Дать доступ" не делает запрос к серверу** — сразу выдаёт уровень 1
5. **Без доступа к localhost корс не даст работать с файлами** — сайт работать не сможет

---

## Текущие проблемы (для проверки)

1. Кнопка появляется на всех страницах при повторной загрузке — проверить кэширование
2. Кнопка не нажимается — проверить метод `requestAccess()`
3. Проверить, что `access_granted_via_button` предотвращает повторную проверку localhost

## Эндпоинты сервера

- `/api/check-access` — проверка доступа (GET)
- `/get-news` — получение новостей (GET)
- `/save-news` — сохранение новости (POST)
- `/api/delete-news` — удаление новости (DELETE)
- `/api/update-news` — обновление новости (PUT)

## 🚫 ВАЖНО: Отключенные функции на текущем этапе

### ✅ Валидация не реализована/отключена
- Даже если валидатор существует (validator.js), он упрощённый и **не подключается к работе**
- Можно реализовать полноценную валидацию, но **не подключать сейчас**
- Формы принимают любые данные без проверки
- **Не чинить и не подключать на текущем этапе!**

### ✅ Проверка доступа/уровней отключена
- Система управления уровнями (permission-manager, access-levels) **существует, но отключена**
- Тестирование требует смены аккаунтов, что неудобно при постоянной проверке
- Будет реализована и протестирована **в самом конце, разом для всех уровней**
- Не нужно постоянно менять аккаунты при тестировании
- **Не чинить и не подключать на текущем этапе!**

Эти функции можно реализовать, но не подключать сейчас — приоритет на основную функциональность.
